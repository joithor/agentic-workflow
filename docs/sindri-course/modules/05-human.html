Where the human decides

Locked doors instead of signs, the right screen for each call, and verdicts that admit what they didn't prove.

A sign versus a locked door

"Staff only" on a door stops polite visitors. A lock stops everyone. Sindri uses both, and never confuses them: hooks force patterns on a cooperative agent; the sandbox enforces security against a hostile one. A hook that fails open costs a missed nudge, never a breach. §5.3, §17.19 C3–C5

writesSign: a pre-tool path guard. Lock: Sindri's verifier refuses any bundle with out-of-scope paths.
commandsSign: a gate on command strings (easily evaded). Lock: missing credentials and network make the command fail anyway.
networkLock only: a per-task egress proxy allowlist.
readsLock: mounts. Only the repo, pack and allowed refs exist in the container (designed: a sandbox phase comes before any unattended Step runs).
holdoutsLock: mounted only into evaluator Steps, with a canary example to detect leaks.

Always denied in sessions (v1)

Undraft, merge, close or cancel items, create items, chat posts, gh api writes, workflow triggers, production-mutating MCP tools, kubectl or exec tools. A denied call parks the item with a typed reason; the session never sits on a permission prompt. §8.1

Nothing secret gets written down

No secrets in packs, ledger, logs, notifications or the eval corpus (invariant 8). Everything passes through the scrubber first, which replaces each secret with a [REDACTED:kind] placeholder. built

sindri/src/scrub/scrub.ts 
export function makeScrubber(extra: readonly ScrubPattern[] = []): Scrubber {
  const patterns = [...BUILTIN_PATTERNS, ...extra].map((p, order) => ({ ...p, re: withFlags(p.re), order }));
  // Only a placeholder naming one of this scrubber's kinds is skipped, so a crafted
  // "[REDACTED:<secret>]" is still scanned.
  const kinds = [...new Set(patterns.map((p) => p.kind))].map(escapeRe).join("|");
  const PLACEHOLDER = new RegExp(`\\[REDACTED:(?:${kinds})\\]`, "g");

The right screen for each decision

A newsroom editor approves a headline from their phone, but rewrites a story at the desk. One command layer is the authority; the CLI and the Sindri app are two clients of the same handler, with the same checks and the same ledger record. §10, §17.12, §17.27

Production stops when review is full

A conveyor belt that outruns the inspector just builds a pile. When the pending-decision queue reaches its limit (default 3 per ring), no new Step that needs a human decision starts (invariant 18). This is back-pressure. Autonomy also follows who gets hurt, not just size:

🧪
sandbox

Auto-start ≤ S, epicMerge auto allowed, fast evidence, sampled human reads

🏠
personal

Auto-start ≤ XS, auto merge allowed, full evidence, samples plus every protected path

👥
shared

Auto-start off by default, no auto merge, full evidence, a human reads every PR

🏭
production

Off, off, deep evidence including mutation testing, a human reads every diff

Rings: home first, then work

Each piece switches on first on ring 0, then ring 1. Ring 2 starts only after the factory holds on ring 1. Work and personal never mix: not in data, accounts or hosts. §13.3, §17.19 C10

0
Ring 0: this toolkit

Sindri builds Sindri from its own plan files. Every new piece runs here first.

1
Ring 1: workplace repos, on work hosts only

Where the factory is tested and improved first. Assist mode, packets, compiler, evidence and lenses on. Auto merge, phone decisions and standing workflows above "report" stay off until the workplace allows them.

2
Ring 2: a private product repo

Started only after ring 1 holds.
