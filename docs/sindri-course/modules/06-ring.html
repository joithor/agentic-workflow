Two jars: stable and next

The harness always runs from a pinned stable install of itself. Changes land on next, are evaluated by stable, soak, then promote. A change may never modify the eval suite that judges it (invariant 11). Here's the gate:

sindri/src/evolve/channel.ts 
  if (c.next === null) return { ok: false, why: "nothing is installed on next", next: "scripts/install-sindri.sh --channel next --ref <sha>" };
  if (c.next.sha !== sha) return { ok: false, why: `${sha} is not what next runs (${c.next.sha})`, next: `sindri channel promote ${c.next.sha}` };
  if (c.stable !== null && c.stable.sha === sha) return { ok: false, why: `${sha} is already stable`, next: "sindri channel status" };
  const days = Math.floor((now.getTime() - Date.parse(c.next.installedAt)) / 86_400_000);
  if (!Number.isFinite(days)) return { ok: false, why: `next has no readable install time (${JSON.stringify(c.next.installedAt)}), so its soak can't be checked`, next: "scripts/install-sindri.sh --channel next --ref <sha>" };
  if (days < SOAK_DAYS) return { ok: false, why: `next has soaked ${days} of ${SOAK_DAYS} days`, next: "sindri channel status (after the soak)" };
PLAIN ENGLISH

Nothing on next? Nothing to promote. Here's the command to install it.

You can only promote exactly what next is running, never some other commit.

Already stable? Nothing to do.

How many whole days has next been running?

If the install time is unreadable, refuse. An unknown soak is not a passed soak.

Not soaked long enough (SOAK_DAYS is 3)? Wait.

Every refusal says why and gives the exact next command to run. The function's last check needs a passing package:sindri suite run at that sha.
