Why Sindri exists

You assign yourself a ticket. Here's everything that should happen next without you.

Start with something you already do

Picture your Monday. You open the tracker, assign yourself a ticket, paste it into an agent session, and then spend the afternoon steering. "No, not that file." "You forgot the migration." "Did you actually run the tests?"

Sindri is a local, always-on harness that takes over that afternoon. It picks up the work, sizes it, starts agent sessions with cited context, keeps them on track and ships them through a fixed recipe. It asks you only when it has to.

⚒️
The name

Sindri is the dwarf smith who forged Draupnir, a ring that makes copies of itself. The core tenet is the same idea: the human approves direction; Sindri does the finding, the building and the proving. Then it uses that factory to improve itself.

Where the work comes from

Before any of that, Sindri has to find work. The built plan-file adapter reads a markdown plan as a backlog, one item per ### Task N: heading. Look at how it handles a missing folder:

sindri/src/adapters/plan-file/tracker.ts 
// A missing repo path or plan dir, an unreadable one, a plan dir with no matching
// plan file, or a plan file too big to read is an error, never an empty backlog:
// an empty scan would make observe mark every item removed.
  async function all(): Promise<Result<Entry[]>> {
    if (!fs.existsSync(dir)) {
      const what = fs.existsSync(o.repoPath) ? `plan dir not found: ${dir}` : `repo path not found: ${o.repoPath}`;
      return err({ kind: "fatal", code: "SND-TRACKER-001", message: what });
    }
PLAIN ENGLISH

If we can't read the plans, that's a loud failure, not "you have no work".

Why so strict? An empty list would look like every task was deleted…

…and the hourly observe job would dutifully mark them all removed.

The scan returns a Result: success with entries, or a typed error.

Say exactly what's missing: the folder, or the whole repo.

Return a fatal error with a stable code (SND-…) you can look up.

💡
Pattern: fail loud, not empty

"Nothing found" and "couldn't look" must never look the same. When you review agent code, ask: what does this return when its input is missing?

What's real today, and what isn't

Sindri is part built, part plan. Every feature in this course carries one of five labels (as of 2026-10-12):

Built built

Merged on main. Plans 1–5 in TypeScript (measurement, the ledger, the code index, scoping and offline self-evolution), and the first stages of the new C# Sindri app: its shell, its command chain and the engine's recipe model.

Building building

Has an open PR. The C# app's API, workflow engine on Temporal, context engine and Avalonia UI are here, in parallel lanes.

Specced specced

Has an approved spec and plan, but no PR yet: the later phases of each app lane.

Designed designed

In a design spec but not planned yet: most of the factory addendum (§17).

Dream dream

Vision, scouting seeds and deferred ideas.

sindri/src/The built part in TypeScript: it runs today and is the reference for the new C# app in src/Sindri, which replaces it at the switch
ledger/The one database everything writes to
lock/Makes sure only one Sindri runs at a time
scope/Brief → cited scope map, plus the backtest
index/The per-repo code index
evolve/Self-improvement: proposals, comparisons, channels
scrub/Strips secrets before anything is stored
