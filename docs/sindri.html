Design overview · 2026-10-08

Sindri

A local, always-on harness that picks up work, scopes it, runs agent sessions with cited context, proves the result, ships it through a fixed recipe, and gets better at all of that on its own. It is named for the dwarf smith who forged Draupnir, the ring that multiplies itself.

03 · What it does

Five jobs, one harness

Every job runs on deterministic code plus bounded model steps. Nothing that runs 24/7 holds a model.

scope

Scope at creation

sindri scope maps every surface, implication and workstream up front, with citations. It is proven by backtesting recall on a project's original brief.

dispatch

Pick up work

It triages the tracker, auto-starts small, clear, trusted items, and queues the rest for scoping. No copy-paste.

context

Keep sessions on track

A cited context pack (intent, stated fix, acceptance, surfaces) is injected at start and re-injected after compaction.

prove

Prove the result

Two-phase verification: trusted checks before push, then the reproduce check against the real environment after a draft push.

ship

Ship by recipe

Draft stacks are worked bottom-up: undraft, resolve reviewer bots and CI, re-draft. The human always merges.

evolve

Improve itself

Skills, prompts, recipes, thresholds and the whole toolkit repo are evaluated blind and evolved within guarded tiers.

04 · How work flows

From tracker to merged PR

The tick is short, deterministic and singleton. Model work happens in bounded jobs and per-item session containers that end when their step does.

05 · Checks that can't be skipped

Hooks enforce. Agents don't opt in.

Every required check fires on a hook event or a Sindri action, never because an agent chose to call a tool. Each one is a loop: produce, deterministic checks, a separate verifier, revise or escalate.

06 · Safety layers

Patterns in hooks, security underneath

A hook that fails open costs a missed nudge, never a breach. The boundary is the layers below.

07 · Self-evolution

It gets better without asking, inside guardrails

The whole toolkit repo, plus every adopted skill, is a managed artifact. Proposals must win a blinded offline comparison and a shadow A/B. Labels come from outcomes, never from hand labeling.

self-adopt

Automatic

Skills, prompts, rubrics, recipes, thresholds. Canary on 25% of items, then 100%. Auto-revert on regression, and a tier brake if too many revert.

approval

Needs the human

Protected surfaces: allowlists, trust lists, hooks, budgets, eval suites, egress.

code

A PR to this repo

Built by Sindri as a normal item, judged by the stable channel. Merged from a daily digest.

08 · Bootstrapping ladder

Sindri builds Sindri

Each piece switches on the moment its plan merges and starts doing its job on the rest of the build. It runs first on this repo (ring 0, whose backlog is the plan docs, read by a plan-file tracker), then on workplace repos (ring 1). Every plan ends with a "Turn it on" task.

10 · How the design was vetted

Six rounds, five lenses each

Product, architecture, design, devex and security reviewed every revision. HIGH findings converged as each new subsystem was hardened. Design and devex pass; the remaining HIGHs are container mechanics that the spike decides.

Each new subsystem (direction checks, hooks, isolation, containers) brought its own HIGH findings, which the next round resolved.
