# Personas: one video per audience

| Cut | Question | Story | Beats |
| --- | --- | --- | --- |
| Engineering | What do I build, in what order, and what breaks? | the model, then how a value flows through the write and read paths, then rollout and PR order | tables and keys; the worked example through each function; the rollout states and the check between them; the PR dependency graph; one risk |
| Product | What will users see and decide? | one thing to set, a rule per workflow, what changes for the people using it | today's separate settings; the one setting; each workflow reading it; the edit that moves them; what stays the same |
| Design (optional) | Which screens change? | the surfaces list | only when a design packet names the surfaces |

Rules: merge cuts that would draw the same board; drop an audience with nothing to see. The product cut never names tables, flags or services; the engineering cut never explains what the product is for. Both use the same worked example so the numbers agree.
