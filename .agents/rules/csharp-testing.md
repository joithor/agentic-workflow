# C# Testing Rules

Source of truth: spec §4b.5 (`docs/superpowers/specs/2026-10-09-agent-readiness-design.md`). The TypeScript test rules (`.agents/rules/testing.md`) still apply to the TS packages until the cutover.

Each rule names the check that enforces it. "Gap — R1b" means the check doesn't exist yet: follow the rule by hand.

| Rule | Check |
|---|---|
| Red test committed before the code | Commit history (the `/specToProvenPR` red-commit rule); review |
| Every test has exactly one `Lane` trait | Partly: `LaneCap` (`LANE-TEST-002`, below) fails a test with several `Lane` traits or an unknown one in any CTRF report it reads, and a test with none in the report of an unfiltered run (a lane filter never selects it). Gap — R1b for the rest. Planned check: a reflection test in `Aw.Architecture.Tests` that loads every `Aw.*.Tests` assembly and fails on any `[Fact]`/`[Theory]` with zero or several `Lane` traits, plus a CI step asserting the unfiltered test count equals the sum of the three lane counts |
| Lane budgets (below) | **Per-test cap:** `LaneCap` in `Aw.Kernel.Testing` (`LANE-TEST-001`) checks each test's own time in xUnit's CTRF report against its lane's budget: run the lane with `--report-xunit-ctrf --report-xunit-ctrf-filename <lane>.json --results-directory <dir>`, then `dotnet run scripts/ci/lane-cap/LaneCapCli.cs -- <dir>/<lane>.json` (exit 0 pass, 1 a violation, 2 a usage or input error; each failure prints the rule id, the package, the test, the measured seconds, the limit and the fix). **Per-package wall clock:** gap — R1b. Planned check: the CI lane job takes the wall clock of `dotnet test --project <test project> --filter-trait "Lane=<lane>" --ignore-exit-code 8` per test project, sums it per package, and fails a package over its budget, printing the rule id, the measured seconds, the limit and the package |
| No mocking libraries | Not in `Directory.Packages.props`; review rejects them |
| A fake and its SQL implementation pass the same contract tests | The contract-test base (per port): for the Kernel ports `ReadRepositoryContract`, `UnitOfWorkContract` and `OutboxContract` in `Aw.Kernel.Testing`, bound to the fakes there and to the `Aw.Kernel.Data` adapters in `tests/Aw.Kernel.Data.Tests`; review checks every new port has one |
| Architecture rules (§4b.1) | ArchUnitNET in `tests/Aw.Architecture.Tests` (gap — R1b until it exists) |
| DI validation per host | The host's `HostTests` (generated by `/new-package`) |

## Red first

- Every slice starts with a failing test that names the behavior: `StartItem_parks_when_budget_is_exhausted`.
- The red commit compiles: it carries the test plus request and response records and a service stub with **no constructor parameters** whose `Handle` throws `NotSupportedException` (an unread constructor parameter is `CS9113` and a `NotImplementedException` is `MA0025`, both errors). `dotnet build` stays at zero warnings and the test fails at run time. The ports arrive in the implement step. `/new-slice` generates exactly that.
- A red placeholder is `Assert.Fail("red: <what to assert>")`, never a `TODO` comment (`MA0026` is an error).

## Organization

- Tests by **feature**, not by layer: `StartItemTests`, not `ItemRepositoryTests` + `ItemServiceTests`.
- Per package: `tests/Aw.<Pkg>.Tests/` (by feature) and `tests/Aw.<Pkg>.Testing/` (fakes, builders, contract bases); project names and root namespaces match their folders, like `tests/Aw.Architecture.Tests/`, which holds every §4b.1 rule.
- `Aw.<Pkg>.Testing` is **test-support** (as `deps.yaml` marks `KernelTesting` with `test: true`): it may reference test-support packages such as `Aw.Kernel.Testing` (the generic contract bases) without a declared edge, only `*.Tests` and `*.Testing` projects may reference it, and it's exempt from fan-out like `*.Tests`. `*.Tests` projects are leaves: nothing references them. Check: `node scripts/check-deps.mjs`.
- Tests reach `internal` types through `InternalsVisibleTo`: `Core`, `Features` and `Infrastructure` declare it for `Aw.<Pkg>.Tests` and `Aw.<Pkg>.Testing`; `Host` declares it for `Aw.<Pkg>.Tests` only. In the small shape `App` declares it for both, and `Aw.<Pkg>.Testing` declares it for `Aw.<Pkg>.Tests` because its builders over `App`'s internal records are internal.
- The test policy applies **by location**: every `*.Tests` and `*.Testing` project lives under `tests/` (including `tests/Aw.Kernel.Testing/`), and #89's `tests/.editorconfig` (`root = false`) covers everything there; outside `tests/` it doesn't apply. It sets: `CA1707` (underscore test names), `RS0016`, `RS0017`, `RS0036`, `RS0037` (no public-API tracking), `CA2007` and `CA1515` (xUnit needs public test classes; xUnit1030 forbids `ConfigureAwait(false)` in tests) are off; `GenerateDocumentationFile` stays `true` (IDE0005 needs it) with `CS1591` off. Test classes are `public sealed`, test names use underscores, and tests `await` without `ConfigureAwait`. `Aw.<Pkg>.Testing` code (fakes, builders, contract bases) gets the same policy because it lives under `tests/` too.
- One top-level type per file, named after it (`MA0048`): builders go in `A.cs`, not `Builders.cs`.

## Lanes

Lanes are xUnit traits named `Lane`. Every test carries exactly one. A budget covers the **whole package's run of that lane** (spec §4b.5: "under 10 s per package"), not a single test, and it is also the cap on each single test (`LaneCap`, table above); the per-package check is a gap — R1b.

| Lane | What | Budget (whole lane, per package) |
|---|---|---|
| `unit` | `Core` logic and services with in-memory fakes; architecture tests. No I/O | < 10 s |
| `integration` | Repositories on a real temp SQLite file; endpoints through `WebApplicationFactory` | < 60 s |
| `heavy` | Real containers, browsers, index builds | none; nightly or run alone (heavy-job lock) |

```csharp
[Fact, Trait("Lane", "unit")]
public void StartItem_parks_when_budget_is_exhausted() { … }
```

Run a lane (xUnit v3 on Microsoft.Testing.Platform, which needs `"test": { "runner": "Microsoft.Testing.Platform" }` in `global.json`):

```bash
dotnet test --solution AgenticWorkflow.slnx --filter-trait "Lane=unit" --ignore-exit-code 8
dotnet test --solution AgenticWorkflow.slnx --filter-not-trait "Lane=heavy" --ignore-exit-code 8
```

Exit code 8 means a test project had no test in the filtered lane (an integration-only project in the unit lane, for example). It is fine **only for filtered runs**, hence `--ignore-exit-code 8` there. The unfiltered `dotnet test --solution AgenticWorkflow.slnx` keeps 8 as a failure: a project with no tests at all is a mistake.

The test framework is decided (R7, R1a spike): xUnit v3 on Microsoft.Testing.Platform, lanes as traits.

## Fakes, not mocks

- Each port has **one** in-memory fake in `Aw.<Pkg>.Testing`. No mocking libraries (Moq, NSubstitute, FakeItEasy): they're not in `Directory.Packages.props` and review rejects them.
- A generic contract-test base (`ReadRepositoryContract<TEntity, TId>`, `ItemRepositoryContract`) runs the **same tests against the fake and the SQL implementation**, so the fake can't drift. Every new port gets its contract base in the same PR as its fake.
- The Kernel ports ship theirs in `Aw.Kernel.Testing`: `ReadRepositoryContract<TEntity, TId>`, `UnitOfWorkContract` (fake: `InMemoryUnitOfWorkFactory`, whose `InMemoryUnitOfWork.Enlist` lets a package's fake repositories write only on commit) and `OutboxContract` (fake: `InMemoryOutbox`). A binding is a sealed test class deriving from the base, with `[Lane(TestLane.Unit)]` for a fake and `[Lane(TestLane.Integration)]` for SQL (`tests/Aw.Kernel.Data.Tests/Sqlite*ContractTests.cs`).

## Test data

- Builders with sensible defaults: `AnItem().WithSize(S).Build()`.
- Deterministic ids (a fake `IIdGenerator`) and `FakeTimeProvider`; never the wall clock or `Guid.NewGuid` in a test.
- No shared mutable fixtures; each test builds its own state.
- Golden files for CLI output and JSON contracts, recorded from the **C# build** (the golden-file assertions live in `Aw.Kernel.Testing`). Compare after the declared normalization (ids, times), never by loose matching. Update a golden file only in a reviewed change that says why the contract changed.

## Architecture tests

ArchUnitNET (not NetArchTest), in the `unit` lane: dependency directions, no slice-to-slice references, `internal` row types, no namespace cycles, naming (no `Common`/`Utils`/`Helpers`). Each test's failure message names the rule id, what it found and the fix.

## Hosts

Every host has a DI validation test that calls the host's own `Compose` method (the one `Program.cs` calls), passing a test environment (a lambda, e.g. pointing `AW_STATE_DIR` at a temp directory) and a `FakeTimeProvider`, builds the container with `ValidateOnBuild` and `ValidateScopes`, and then resolves every registered `IService<,>` inside a scope (decorators are factory registrations that `ValidateOnBuild` can't see into).
